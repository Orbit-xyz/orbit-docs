title: "Quickstart"
description: "Go from two funded testnet accounts to a settled recurring pull in about five minutes."
---

This guide runs a full billing cycle against the deployed Orbit contract on Stellar Testnet using only the Stellar CLI.

## Prerequisites

- [Stellar CLI](https://developers.stellar.org/docs/tools/stellar-cli) installed
- A terminal with `bash`

## Set up

<Steps>
  <Step title="Export the network constants">
    ```bash
    export ORBIT=CAZBZBUWBSQYK2RZ6WHMXVDLIQHSU5WD7ANZYL6HLNSCRUOTNYCDYQNG

    # Testnet native-asset SAC. Use it as a stand-in for USDC so no trustline is needed.
    export TOKEN=$(stellar contract id asset --asset native --network testnet)
    ```
  </Step>

  <Step title="Create and fund three identities">
    ```bash
    stellar keys generate merchant   --network testnet --fund
    stellar keys generate subscriber --network testnet --fund
    stellar keys generate contractor --network testnet --fund

    export MERCHANT=$(stellar keys address merchant)
    export SUBSCRIBER=$(stellar keys address subscriber)
    export CONTRACTOR=$(stellar keys address contractor)
    ```
  </Step>
</Steps>

## Run a billing cycle

<Steps>
  <Step title="Subscriber approves Orbit on the token">
    The allowance caps the total Orbit can ever move for this subscriber. This one covers 12 cycles of 29 units.

    ```bash
    stellar contract invoke --id $TOKEN --source subscriber --network testnet -- \
      approve \
      --from $SUBSCRIBER \
      --spender $ORBIT \
      --amount 3480000000 \
      --live_until_ledger 5000000
    ```

    <Warning>
      `live_until_ledger` must be in the future and within the network's maximum entry TTL. After that ledger the allowance expires and every pull fails.
    </Warning>
  </Step>

  <Step title="Subscriber creates the vault">
    29 units every 30 days (`2592000` seconds). No tokens move at this step.

    ```bash
    stellar contract invoke --id $ORBIT --source subscriber --network testnet -- \
      create_vault \
      --user $SUBSCRIBER \
      --merchant $MERCHANT \
      --token $TOKEN \
      --amount_per_interval 290000000 \
      --interval_seconds 2592000
    ```
  </Step>

  <Step title="Merchant pulls the first cycle">
    The first pull on a new vault is allowed immediately.

    ```bash
    stellar contract invoke --id $ORBIT --source merchant --network testnet -- \
      pull_funds --user $SUBSCRIBER --merchant $MERCHANT
    ```
  </Step>

  <Step title="Confirm the cadence guard">
    Run the same pull again. It fails with `Too early to pull funds` because 30 days have not passed on the ledger.

    ```bash
    stellar contract invoke --id $ORBIT --source merchant --network testnet -- \
      pull_funds --user $SUBSCRIBER --merchant $MERCHANT
    # Error: ... Too early to pull funds
    ```
  </Step>
</Steps>

## Pay a contractor

<Steps>
  <Step title="Merchant approves Orbit for the payroll total">
    ```bash
    stellar contract invoke --id $TOKEN --source merchant --network testnet -- \
      approve --from $MERCHANT --spender $ORBIT --amount 100000000 --live_until_ledger 5000000
    ```
  </Step>

  <Step title="Disburse">
    ```bash
    stellar contract invoke --id $ORBIT --source merchant --network testnet -- \
      batch_disburse \
      --sender $MERCHANT \
      --token $TOKEN \
      --splits '[{"recipient":"'$CONTRACTOR'","amount":"100000000"}]'
    ```
  </Step>
</Steps>

<Check>
  You have opened a vault, settled a pull, seen the cadence guard reject a second pull, and run a payroll. Look up each transaction on [stellar.expert](https://stellar.expert/explorer/testnet/contract/CAZBZBUWBSQYK2RZ6WHMXVDLIQHSU5WD7ANZYL6HLNSCRUOTNYCDYQNG).
</Check>
